Website integration

Lead generation calculators

Embed calculators in your website and collect leads for adviser follow-up. Start with mortgage and home equity calculators for Danish homeowners.

The current calculators use Danish interface text and amounts in DKK. This integration guide is in English.

How it works

Råd til Bolig provides hosted web components that render inline on your CMS page. The current mortgage and home equity flows collect address, loan and contact details before showing the result.

Loan Check (Lånetjek)
Calculates a refinancing scenario from the property and loan inputs. The flow saves the proposal with the customer's property for adviser follow-up.
Home Equity (Friværdi)
Shows estimated property value, debt and potential equity release from the calculation inputs.

Submitting the contact step creates the customer and property record with the supplied loans. Company routing follows the website origin registered with Råd til Bolig. Results depend on the property and loan inputs and require an adviser's review before a financing decision.

Before you start

Agree these installation values with Råd til Bolig for both staging and production:

  • Website origins: the exact HTTPS origins that will host the calculators, for example https://www.example.com. Register preview subdomains separately.
  • Asset origin: the supplied host for the component bundle, theme, fonts, images and recommendation files in each environment.
  • Theme class: the CSS class supplied with your theme.
  • Brand and links: your company display name, privacy policy URL and adviser name.

The component bundle selects its API and platform services at build time. Use the matching asset origin for each environment. Råd til Bolig configures origin access and company routing on the server.

Load the components

Add these imports once per page. Replace every ASSET_ORIGIN with your supplied HTTPS asset origin, without a trailing slash, and replace the company and privacy examples. Place the configuration before the module scripts.

<link rel="stylesheet" href="ASSET_ORIGIN/app.css">
<link rel="stylesheet" href="ASSET_ORIGIN/fonts.css">

<script>
  window.RAAD_TIL_BOLIG = window.RAAD_TIL_BOLIG || {};
  window.RAAD_TIL_BOLIG.config = {
    brandName: "YOUR_COMPANY_NAME",
    privacyUrl: "https://www.example.com/privacy"
  };
</script>

<script type="module"
  src="ASSET_ORIGIN/static/components/components.esm.js"></script>
<script type="module"
  src="ASSET_ORIGIN/static/assets/ionicons/ionicons.esm.js"></script>

Keep one component version and one Ionicons import on each page. The CMS owns the page layout, header, cookie banner and analytics configuration. Leave initializeSite unset for an inline CMS integration.

Embed Loan Check

Place the following markup in the page's content area. Replace YOUR_THEME_CLASS and YOUR_ADVISER_NAME with your installation values.

<div class="YOUR_THEME_CLASS">
  <app-calculator-inline sync-url="false" url-prefix="loan-check">
    <app-calculator-state-address
      state="address" label="Address" pagination>
    </app-calculator-state-address>
    <app-calculator-state-loans
      state="loans" label="Loans" pagination>
    </app-calculator-state-loans>
    <app-calculator-state-contact
      state="contact" label="Contact" pagination>
    </app-calculator-state-contact>
    <app-rebalance-state-result
      state="result" advisorname="YOUR_ADVISER_NAME">
    </app-rebalance-state-result>
  </app-calculator-inline>
</div>

Configuration and browser state

brandName and privacyUrl
Set the company name shown in the contact consent text and the destination of its privacy link. Company routing is configured server-side for the website origin.
sync-url="false"
Keeps the CMS page's URL hash intact while the calculator changes steps.
url-prefix
Identifies the calculator's saved browser state. Use distinct, stable values for the two flows. Saved state is restored when it is up to 24 hours old; expired state is removed when the calculator next reads it.
advisorname
Sets the adviser name on the result. The adviser image comes from the supplied asset bundle.
recommendationCtaUrl and recommendationCtaLabel
Optional fields in window.RAAD_TIL_BOLIG.config. Set both to add a contact link with your chosen text to the recommendation card.

The step labels in these examples customise navigation labels. Other interface text comes from the Danish component bundle.

The flow uses local storage for calculator state and a customer_token cookie for subsequent customer updates. The cookie expires after one hour. Review the actual storage and consent behaviour with your site's privacy and consent setup.

CMS and security policy

Your CMS must preserve custom elements and type="module" scripts. Use its supported HTML or code integration facility and check the published page, since editors can strip tags when saving.

The components request their calculator token automatically from the platform's /v2/calculator/token endpoint. Råd til Bolig registers the exact website origin and enables the required cross-origin access for the platform, API and assets.

If your site uses a Content Security Policy, allow the supplied asset host for scripts, styles, fonts and images; the matching API and platform hosts for connections; and blob: images used for property photos. Include any Google Fonts origins referenced by your supplied theme.

Apply the CMS-generated nonce to the inline configuration script when your policy requires it. If generated component styles also require a nonce, add this tag to the page's <head> before the component scripts:

<meta name="csp-nonce" content="CMS_NONCE">

Replace CMS_NONCE with the current response's nonce. Match the allowed hosts and nonce handling to the actual CMS policy.

Before launch

Run both flows on your published staging pages, then repeat the checks on production. Use agreed test records and verify the resulting records with your Råd til Bolig contact.

  1. Complete address, loans, contact and result steps on desktop and mobile, including the narrowest content column used by your CMS.
  2. Check fonts, icons, property photos, adviser image, recommendation text and privacy and contact links.
  3. Confirm the customer and property reach the correct company, and that Loan Check saves the proposal.
  4. Check that surrounding page styles, navigation and URL hashes behave as expected. Reload a partially completed flow and check restored state.
  5. Check blocked requests, unavailable recommendation files and API failures. Confirm the displayed result and recovery behaviour with Råd til Bolig before accepting the integration.
  6. Confirm the contact consent wording and browser storage behaviour against your site's configuration.

Installation requires a check on your actual website. The supplied markup depends on registered origins, published assets and the CMS security policy. Keep the previous CMS version so you can restore it if an installation fails.

Troubleshooting

The calculator is empty
Check that the CMS kept the custom elements and module scripts. Inspect the browser's console and network panel for blocked scripts or an incorrect asset origin.
Requests fail with a CORS or authorisation error
Verify the exact website origin, including its scheme and subdomain, with Råd til Bolig. Confirm that all imports use the agreed environment.
Fonts, images or recommendations are missing
Check asset responses, the supplied theme class and Content Security Policy. Share the failed URL and response status with your integration contact, excluding tokens and customer data.
The result is clipped or loading does not finish
Check the CMS column width and failed network requests. Include the affected step, browser and viewport size when reporting the issue to Råd til Bolig. Resolve it before launch.
